01

the big picture

one full-stack TanStack Start app compiled into one worker. cloudflare's edge terminates TLS, replays early hints, and serves hashed assets; every dynamic request runs the worker, which talks to D1 over a binding and reaches out to a small set of managed services.

why

smart placement

placement.mode = "smart" runs the worker near the d1 primary in western europe instead of near the visitor — per-request db round-trips dominate over first-hop latency, so co-locating compute with data wins.

why

early hints

the worker appends Link preload headers to every html response; the edge caches them and replays an http 103 with css + geist font preloads before the worker even starts rendering.

why

one bundle

vite + @cloudflare/vite-plugin compile ssr, server functions, api routes, and cron handlers into a single worker script — one deploy artifact, one runtime to reason about.

02

anatomy of a request

workers forbid sharing i/o objects across requests and kill unawaited promises once the response returns. the entry file solves both with AsyncLocalStorage seams: each request gets its own drizzle instance and its own ctx.waitUntil channel, invisible to domain code.

the db proxy — two drivers, one import 

// src/db/index.ts — every domain module just imports { db }
export const db: Db = new Proxy({} as Db, {
  get(_target, prop) {
    // workers: per-request drizzle(d1) from AsyncLocalStorage
    // bun (tests/scripts): libsql against file: DATABASE_URL
    const target = dbStorage.getStore()
      ?? (fallbackDb ??= createLibsqlDb())
    ...
  },
})

domain code never knows which driver it runs on. integration tests hit an ephemeral sqlite file with the same async, batch()-capable semantics as d1 — no docker, no external services.

background work must opt in 

// src/lib/execution-context.ts
// unawaited promises die when the response returns,
// so all fire-and-forget flows through waitUntil:
background(sendNotifications(...), "messages.notify")
// → ctx.waitUntil(guarded) on workers
// → plain fire-and-forget in tests/scripts

rejections are logged under the tag, never thrown. this one seam is why notifications, digest fan-out, and mux cleanup can be fire-and-forget without being silently killed by the runtime.

03

domain layer

every feature lives in src/lib/<domain> with the same four-file shape, exported as a facade object. routes consume the facade through the loader + suspense pattern, so ssr and client navigation share exactly one data path.

the facade shape

src/lib/{domain}/
├── fns.ts      # createServerFn() endpoints
├── schemas.ts  # zod input validation
├── hooks.ts    # react-query mutations
└── index.ts    # facade export

// consumed by routes:
loader: async ({ context }) => {
  await context.queryClient.ensureQueryData(
    tricks.get.queryOptions({ trickId }),
  )
}
// component: useSuspenseQuery(same options)

server functions get readable, stable rpc ids (/_serverFn/lib_feedback_fns_submitFeedback…) via a custom generateFunctionId in vite.config.ts, so access logs name real functions instead of hashes.

engagement, systematized 

// per entity (posts, sets, videos, tricks, …):
{entity}Likes         # pk: entityId + userId
{entity}Messages      # comment thread
{entity}MessageLikes  # pk: {entity}MessageId + userId

the reactions module builds column names dynamically (`${type}Id`), so one generic implementation powers likes and messages across every entity in the app — the schema convention is load-bearing.

tricks

04

auth — passwordless codes

no passwords stored, no oauth dependency. a rider asks for a code, resend delivers it, and a signed session cookie carries the rest.

05

video pipeline — mux

video is the heart of the product — landings, game submissions, vault clips. uploads bypass the worker entirely: the browser streams straight to mux, and the worker only handles metadata and webhooks.

06

scheduled work

no queue, no separate job runner — the same worker exposes a scheduled() handler and dispatches on the cron expression. background fan-out rides ctx.waitUntil.

mondays 00:00 		rotate() riu round rotation — archives the finished round, activates the next, opens a new one. constant lives in src/lib/games/rius/lifecycle.ts, kept in sync with wrangler.jsonc.

sendGameStartReminders() 		notification digests honor each rider's configured hour/day; game-start reminders check hours-until-rotation within a one-hour window. both email via resend.
07

deploy pipeline

continuous deployment with a single serialized lane: push to main, and github actions does the rest. rollback is a worker-version revert in the cloudflare dash — which is why migrations are roll-forward only and must stay backward-compatible with the previous worker.

08

performance & observability

performance

  • compute near data — smart placement pins the worker beside the d1 primary; the dominant cost is the many small sql round-trips per request, not the visitor's first hop.
  • 103 early hints — css and latin-subset geist fonts preload from the edge before ssr even starts.
  • immutable assets — hashed build output cached forever at the edge.
  • lazy heavy views — trick graph (xyflow), maps (maplibre), and charts load on demand.
  • ssr without flashes — loaders await ensureQueryData; mutations use optimistic updates or removeQueries + navigate, never stale-flash invalidate.
  • d1 discipline — stats queries chunk UNION ALL chains under d1's 5-term compound-select limit.

observability

  • structured logs — one json line per event with requestId and userId stamped from request-context ALS; one access-log line per request (method, path, status, duration). tail via workers logs.
  • sentry, both sides — @sentry/cloudflare wraps the worker (20% traces in prod), the tanstack-start client sdk covers the browser; source maps upload in ci.
  • named rpc ids — server-function urls read lib_feedback_fns_submitFeedback…, so logs name real functions.
  • deploy visibility — status on every commit; version history + one-click rollback in the cloudflare dash.
  • backups — d1 time travel, 30-day point-in-time restore.
